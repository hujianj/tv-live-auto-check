## Repairs in this continuation

- Accept interlaced `576i`/`1080i` resolution suffixes throughout identity and scope
  handling, including harmless whitespace. CCTV-4K is not counted as CCTV-4.
- Aborted strict rechecks now record actual checks and failures, retain original
  outputs, and distinguish candidate row counts from promoted row counts.
- Recheck CSV preserves the real source even for removed/failed rows.
- Diagnostic reports include broad-pass failures and distinguish unperformed
  checks (`null`) from a measured failure. Stale evidence cannot make an export ready.
- Metadata joins use canonical identity, URL and source; ambiguous origins and
  incompatible channel aliases cannot inherit each other's approval.
- Legacy source contribution counters are explicitly labeled as pre-policy
  parsing counts, separate from media-eligible and final output sources.
- The existing test entry point now runs 87 original and 24 pipeline tests, all passing.

## Confirmed production timeout and decoding repair

Run 177 (`34131922967`, job `101773804843`) ran revision `d44e6a5`.
Its captured log proves two distinct 1800-second timeouts in `verify_sources.py`:
14:45:16 UTC and 15:15:36 UTC. Both attempts start from 22,849 unique URLs.
The second attempt did not resume the first attempt's approximately 9,000
successful broad probes. Commit, purge and CDN verification were skipped.
This is not the workflow's 180-minute job timeout and not a CDN refresh failure.

The repair branch filters publication-ineligible candidates before media probes,
bounds each URL across subrequests and retries, and checkpoints successful broad
probes for reuse only in the same run and policy. Failed probes are retried;
different runs, changed rules and guard confirmation passes cannot inherit success.
Final selected URLs always receive a new strict check.

Final checks now require three decoded video frames, including slow retries and
historical/refill candidates. Initialization-aware fMP4 probing is covered with
a real offline fixture. FFmpeg receives bounded downloaded bytes through pipes,
not upstream URLs. Missing decoding evidence blocks final publication and exports.
`requirements.txt` and the Actions workflow install the same pinned decoder package.
The existing test entry point passes 87 original, 28 pipeline and 5 real-decoder
tests. Python compilation and whitespace validation pass.

Manual dispatch on the repair branch now permits a non-publishing validation run.
The workflow still hard-gates repository commits to the default branch; branch
validation cannot purge the television CDN or change the main maintenance alert.
This enables cloud validation before merging without weakening coverage gates.

The earlier 12:59 UTC local run completed 127 broad URL probes and 13 strict
video-track checks in 377 seconds, then failed core coverage. It predates the
frame-decoder integration and is not evidence of successful frame decoding.
Neither that run nor the offline tests constitute a new public subscription.

Cloud validation run 180 (`34140632073`) tested repair `53fce40`. All 120 tests
passed on Ubuntu with system FFmpeg. Collection parsed 26,220 rows, selected
318 eligible candidates and finished all 243 unique broad probes in 63.8 seconds.
This reproduces the timeout repair in the actual Actions environment without
raising the 1800-second limit. Final recheck held publication: 9/29 URLs failed
after the low-concurrency retry, exceeding the unchanged 25% failure-ratio guard.
Seven manifests did not advance and two short TS probes observed only audio.
Twenty diagnostic rows passed actual frame decoding; they were not published.

The follow-up repair lets real video decoding, not a short TS track sample,
decide whether those two streams carry video. It first downloads 512 KiB and
only expands the sample to 4 MiB if decoding needs more data. Broadcast checks
also decode the new live-edge segment after manifest advancement. A failed
progress check preserves any frames already decoded in diagnostic counters.
Three additional regressions pass, for 123 tests total. These changes do not
relax the source-permission, missing-channel or failed-URL publication guards.

## September 8 deployment preparation

Cloud run 181 (`34141636068`, revision `9c44a30`) passed all 123 tests and
finished all 243 eligible broad checks in 64.8 seconds. Final checks failed
10/28 URLs after retry: seven non-advancing manifests, one HTTP 404 and two
actual video-decoding failures. The adaptive sample did not prove those two
channels playable; their failures remain failures. Eighteen diagnostic rows
passed, but no subscription file was published. The full job took 3m14s.

The previous requirement to wait for a complete replacement bundle before any
code deployment leaves scheduled main running the known timeout bug indefinitely.
Deploy the verified code separately while preserving every committed playlist,
report and manifest byte. This does not waive the new-publication gates.
Fast CI separates code validation from existing publication integrity, with both
checks mandatory for a completely green result. Existing integrity failures stay
visible; no `continue-on-error`, counter rewriting or fabricated media evidence.
Maintenance summaries and alerts distinguish a timeout from a playback gate hold
and state explicitly when the subscription was not updated.
