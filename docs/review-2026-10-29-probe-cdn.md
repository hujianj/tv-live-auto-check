# 2026-10-29 媒体取样与分发分级修复

## 已定位问题与修复

1. 原推荐固定地址是 gh-proxy，但必需主门禁仍是 jsDelivr。将必需主端点改为 ghproxy_raw；所有配置端点仍实查固定 URL 和对应文件哈希，Raw/主失败仍阻断分发，备用失败明确降级并保留告警。
2. 仅凭主分发成功关闭 CDN Issue 会掩盖备用滞后。通知读取完整端点证据并重算状态；只有全部受检电视镜像恢复才关闭。required-only 证据不允许关闭全镜像告警。
3. 重试若被 watchdog 杀死可能遗留上一轮健康报告。每轮先移除旧工作报告（此前已留档），通知同时检查实际步骤 outcome；报告缺失/矛盾保留未知分发告警，不能误判恢复。
4. validate-only 之前漏校验家用完整 TXT。现在预检所有端点对应的独立文件，格式失败不访问或清除 CDN。
5. 4 KiB 初筛可能未含 TS 轨道表。仅对完整但不确定的 TS 样本有限扩到 32/128 KiB，共享原绝对超时；HTML、已确认纯音频不因此放行，最终真实解码和 HLS 推进门禁不变。
6. MPEG-TS 有 PMT 先于 PAT、半截 PSI 起始和丢包后新 PUSI。采用两遍 PAT/PMT 探测并在 pointer 新边界丢弃旧片段，不把同步字节视为视频成功。
7. README 旧段落仍写 jsDelivr 是必需主，已统一为配置中的固定 Raw 代理主地址。

- 四条先前 unknown/mpeg-ts 的实际线路扩大样本仍未证明视频，本轮保持失败。进一步辽宁候选调查读取超时，也不能宣布恢复。

## 保留约束

- 可播放线路不按本机/云端测速淘汰、排序；完整目录不按每台严格限量裁减。
- 家用完整目录只在央视/卫视频道无任何严格成功线路时补实际合规候选，明确待电视复核，不记入成功历史。
- 不新增 Token/DRM/鉴权绕过或私网来源，不下载/执行来源程序。
- 第三方固定代理和 CDN 仍可能不可达；一次成功只证明当时受检网络与缓存边缘。
